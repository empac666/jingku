# Screenshot provenance / 截图来源

Four **HTML high-fidelity UI renders**, not Android emulator or physical-device captures:

- `01-import-index.png`: imported video queue and indexing progress.
- `02-search-results.png`: Top-3 transcript cards with literal highlighting and timestamps.
- `03-playback-seek.png`: illustrative player seek state (no actual HTML playback).
- `04-low-confidence.png`: dark-theme low-confidence hints.

Each image visibly labels HTML rendering/demo data. Example titles, transcripts, scores, progress and thumbnails are synthetic. They do not show real model inference, measured latency or proven device playback. The landscape illustration was generated in SVG code, not extracted from copyrighted footage. No evaluation videos were redistributed.

Source: `render/*.html`, generated by `render/render.py`; Chrome headless rendered at 432×960 CSS pixels with device scale 2.5 (1080×2400 PNG). Android `activity_main.xml`, `item_search_result.xml` and Material 3 color values informed this approximation. Some sections are scrolled/expanded to focus on the target state; spacing and extra explanatory demo labels may differ from the app. Temporary debug preview scaffolding was removed from final source; demonstration fixtures exist only in these HTML files.

Emulator attempted first: installed emulator + Android 30 Google APIs image, configured KVM, launched headless AVD, but no adb device appeared and SDK/AVD data reduced free disk to 9.8 GiB. Removed this task's image/emulator/AVD to respect the 8 GiB floor; existing SDK platform/build tools retained. The fallback rendering is explicitly permitted by the task. No claim of Android runtime visual verification is made.

Reproduce locally from release workspace: `python3 screenshots/render/render.py` then `scripts/render-screenshots.sh` (Chrome required).
